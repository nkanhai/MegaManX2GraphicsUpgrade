# Unity graphics reconstruction prototype

Offline Unity 6 URP inspection of runtime-v1 `.x2scan` captures. The reference
image is only a comparison input. Background textures are decoded from VRAM,
tilemaps and CGRAM; sprite textures and placement come from OAM. There is no
ROM access, live connection, simulation, asset catalogue or game-code change.

This prototype has **verified managed-decoder parity on synthetic frames** and
owner-observed **Unity Metal baseline parity on a real gameplay capture:
0/57,344 pixels different**. That local result is separate from cloud CI and
does not qualify every capture or the lighting experiment. The lighting fix
and additional GPU tests below still require an owner run. See the
[Sprint 4 report](../docs/roadmap/SPRINT_4_REPORT.md) for measured results.

## Open on an Apple Silicon Mac

1. Use the Apple Silicon **Unity 6000.0.62f1** Editor through Unity Hub. Add/open
   this repository's `hd2d/unity` folder as a project. It is an Editor diagnostic
   prototype; a standalone player is not qualified.
2. Let Package Manager resolve `Packages/manifest.json`: **URP 17.0.4** and
   **Unity Test Framework 1.4.6**. Direct versions are pinned; the owner has
   confirmed URP 17.0.4 locally, but the resolved transitive lock is not recorded.
   Do not upgrade packages to work around errors without recording the change.
3. The Editor bootstrap creates a 2D Renderer and URP asset under ignored
   `Assets/LocalGenerated`, selects Gamma color space, disables HDR/MSAA/post
   processing and installs the pipeline. If necessary, run **X2 HD-2D →
   Initialize diagnostic URP settings** after scripts finish compiling.
   URP may also generate ignored `UniversalRenderPipelineGlobalSettings.asset`
   and `DefaultVolumeProfile.asset` at the Assets root.
4. Choose **X2 HD-2D → Open diagnostic scene**. This opens
   `Assets/X2HD2D/Scenes/Diagnostic.unity` and the **X2 Graphics** window. Use the
   window in Edit mode; Play mode is unnecessary. Its render requests drive
   the two 256×224 camera targets. The Game view is not the diagnostic UI.
5. Choose **Import private .x2scan (read only)** and select the final
   `capture.x2scan` from a private directory under `hd2d/local/`. Keep captures
   outside `Assets`; do not drag them into Project view. Nothing is copied or
   converted to saved Unity assets. Reopen the file after a domain reload.

The diagnostic tool is **Edit-Mode-only**. During Play Mode and transitions the
window shows a clear warning and offers no import, rendering, visibility,
lighting or export actions. Scene/setup menus are disabled, and direct calls
are guarded before any save dialog or Editor scene-management operation.
The tool does not cancel Play Mode for the rest of the project.

If Play Mode is entered accidentally, stop it, wait for the Editor transition
to finish, then import the capture again. Transient capture state is discarded
after the return to stable Edit Mode, including when domain/scene reload is
disabled. Cleanup is queued from lifecycle callbacks; it does not change
activation or destroy resources inside `OnDisable`, `OnDestroy` or Play Mode.
A transient `DontSave` resource owner retains cleanup references across Editor
reloads without serializing private graphics into the saved diagnostic scene.

The existing [interactive capture workflow](../docs/guides/INTERACTIVE_CAPTURE.md)
supplies real captures. It is unchanged. Unity needs the completed capture,
not the ROM or the native executable. Run the existing
[`validate_capture.py`](../tools/validate_capture.py) first to establish native
replay parity independently of this prototype. Native replay and Unity GPU
comparison are separate checks, including after an owner-verified Unity frame.

The container reader rejects unknown versions/profiles/engine pins, invalid
sizes/hashes/register values, missing/reordered lines and invalid memory
versions. It never edits its input. Error messages appear in the window.
Runtime v1 is distinct from the Sprint 0 synthetic JSON format, which is not
accepted here. A runtime-v1 capture can have original synthetic source data.

## Inspect independent components

The window shows the original reference, the reconstructed unlit Unity view,
and an isolated lighting experiment. BG1, BG2, BG3 and OAM toggles affect only
the reconstructed view. Restore visibility before comparing the complete frame.

In the scene Hierarchy, each background has two priority quads. A quad's texture
is generated by sampling that layer's original tilemap with its scroll, palette,
tile size and flip attributes. No mesh is generated per tile. The original
tilemap entries remain in the managed model and are selectable by map-cell
coordinates in the inspector. **Preview source 8×8 tile** shows a decoded
unflipped VRAM tile, not a crop from the reference image. For a 16×16 cell it
shows its first source sub-tile.

Each of the 128 OAM slots has a separate root, metadata component and decoded
sprite quad; vertical wrapping may add a second quad. Metadata includes source
slot, evaluation order, screen position, tile number/base, palette, priority,
size and flips. Invisible/offscreen slots remain inspectable. **Select piece in
Hierarchy** selects a slot for ordinary transform/material inspection.
OAM slots are hardware graphics pieces, not semantic or persistent game entities;
scroll values are screen sampling offsets, not a verified world camera.

Sprite ownership and hardware line/tile limits are resolved into per-piece
visibility masks **before** mixing background priorities. Sorting whole sprites
by priority alone is incorrect when a lower-OAM piece hides a later piece that
has higher background priority. `RawRgba` retains the unclipped decoded piece
for inspection/enhancement; baseline quads use `VisibleRgba`. Hiding an individual
OAM root does not recompute ownership to reveal previously occluded pieces.

## Faithful subset and incomplete inspection

The strict importer accepts the established `native-mode1-v1` capture profile.
The managed component renderer supports a **smaller static-frame subset**:

- Mode 1: BG1/BG2 4bpp and BG3 2bpp, 8/16-pixel cells, 32/64-cell maps,
  scroll/wrap, palettes, horizontal/vertical flips and BG3 priority selection.
- Main-screen backgrounds, backdrop, square OBJ size modes 0–5, OAM rotation,
  signed X/vertical wrap, tile-bank addressing and original priority metadata.
- Integer RGB5 expansion/brightness, forced blank, native 32-object/34-sliver
  limits and the recorded no-sprite-limits policy; legacy and optimized flags.

These effects are **not reconstructed**:

| Effect | Behaviour |
|---|---|
| Color addition/subtraction, half color, fixed/subscreen math, color-window clipping | Incomplete-support diagnostic; inspection uses main-screen colors |
| Layer windowing | Incomplete-support diagnostic; inspection omits window masks |
| Display-register or VRAM/CGRAM/OAM changes between visible scanlines | Incomplete-support diagnostic with first changed register/line or memory boundary |
| Rectangular OBJ modes 6/7 | Explicitly unqualified; inspection uses the pinned PPU's square approximation |
| Other display modes, mosaic, SETINI, overscan/interlace | Rejected by the runtime-profile reader |
| Widescreen, overlays, live timing, semantic entities, new assets | Outside this recorded native-profile prototype |

For an incomplete frame, **State before scanline** selects one captured memory
and register state and decodes the entire viewport from that state. This lets
developers inspect original components in a real gameplay capture with raster
effects. It does **not** reconstruct the actual raster-varying frame. Line 1 is
the default; line 0 initializes the PPU and is not a displayed row. BG sampling
uses native lines 1–224; OBJ sampling uses rows 0–223. The classifier is
conservative: even an unused memory change can mark a frame incomplete.

## Compare and export evidence

With the original main-screen visibility restored, select **Export private
GPU/reference/component comparison**. The tool submits a fresh URP render
request and reads back the actual baseline camera target. It writes a unique
directory under ignored `hd2d/local/unity-comparisons/` containing:

- `reference.png`: the canonical framebuffer from the capture.
- `unity-components.png`: actual Unity GPU rendering of component quads.
- `managed-components.png`: independent managed compositing of those decoded
  components, useful for separating decode errors from Unity rendering errors.
- `difference.png`: magenta where Unity RGBA differs, black where it agrees.
- `report.json` / `report.txt`: GPU and managed pixel counts, capture digest,
  session/sequence, selected line, Unity version, filter and support status.

`verified-this-frame` requires a supported profile, all top-level visibility
toggles restored, and **both** comparisons at 0/57,344 pixels different.
`mismatch` is a supported frame with differing pixels.
`incomplete-or-filtered-inspection` cannot claim full-frame fidelity even if its
pixels happen to match. Rendering setup errors abort export; an uninitialized
target is never treated as evidence. The claim concerns the pinned PPU output,
not original SNES hardware accuracy or other game frames.

Use a fresh import to discard manual transform/material changes before a
baseline comparison. The renderer uses point-sampled unlit quads, a pixel-sized
orthographic viewport and Gamma space to avoid an extra color transform. Any
remaining platform/texture/render-pipeline difference must be measured, not
assumed away. GPU tests enforce zero differences, with no tolerance threshold.

## Isolated normal-map experiment

Selecting an OAM root or its decoded/wrapped child in the Hierarchy updates the
graphics inspector's OAM slot. **Light this piece in experiment** copies that
slot's raw graphics into the second view. The experiment label identifies its
currently rendered slot separately from the inspector selection. Its sprite is
centered and fitted within the viewport, regardless of the original OAM position.

Use **Experiment stage** in this order to isolate a black view:

1. **Unlit** — built-in unlit material, no experiment light. Confirms source
   pixels, geometry, camera and target visibility.
2. **Global Light** — built-in lit material and one Global Light2D, no normals.
   Confirms the 2D renderer and target sorting layer.
3. **Point Light** — built-in lit material and one moving Point Light2D, no normals.
   Confirms the light mesh, camera depth and spatial illumination.
4. **Normal Map** — the point light plus the procedural `_NormalMap` secondary
   texture and accurate normal mapping. Only this stage uses a treatment's
   optional custom material.

Both sprite and light are on **GameObject layer 9**, visible only to the
experimental camera. The sprite uses sorting layer **Default**, which is
explicitly assigned to the light's **Target Sorting Layers** before activation.
GameObject layers and sorting layers serve different purposes. The light mesh
stays at Z=0, in front of the camera at Z=-10; URP's separate normal-map distance
sets the virtual lighting height. Moving the mesh to Z=-30 puts it behind the
camera and can clip its illumination entirely.

The window reports opaque source pixels and actual GPU nonblack-pixel counts.
Warnings identify fully transparent/black source pixels, missing/disabled
lights, excluded sorting layers, wrong layer/culling masks, offscreen geometry,
invalid render targets and black GPU output despite nonblack source pixels.
An experimental failure hides its stale view and leaves baseline rendering and
comparison export available. Readback at the diagnostic window's 10 Hz refresh
is for inspection, not a continuous-playback performance claim.

The normal map is an experiment, not an inferred original game asset. Desktop
normal packing is used; mobile normal encodings have not been qualified.

Optionally create **Assets → Create → X2 HD-2D → Capture-local treatment** under
`Assets/LocalGenerated`, then assign it to the scene root's `treatment` field
and reimport. It exposes slot selection, tint, scale, normal strength and a
material override. This is a reusable data-driven treatment for the current
capture, not a cross-frame asset mapping or catalogue. Baseline textures,
materials, camera and objects are separate; lighting never feeds baseline
comparison. Generated graphics are marked `DontSave`, so saving the diagnostic
scene does not serialize imported pixels. Keep comparisons and custom private
treatments local.

## ROM-independent tests

From the repository root, with Python 3.10+, CMake, Ninja, a C compiler and SDL2
headers available (`brew install cmake ninja sdl2` on the Mac if needed):

```sh
git submodule update --init --recursive
cmake -S hd2d/tests/native -B hd2d/local/unity-native -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build hd2d/local/unity-native --target scanout_on scanout_replay --parallel 2
hd2d/local/unity-native/scanout_on hd2d/local/unity-source
python3 hd2d/tools/make_unity_fixtures.py \
  --synthetic hd2d/local/unity-source/capture.x2scan \
  --replay hd2d/local/unity-native/scanout_replay \
  --output hd2d/local/unity-fixtures
dotnet run --project hd2d/tests/unity/CoreTests.csproj --configuration Release -- hd2d/local/unity-fixtures
python3 -m unittest discover -s hd2d/tests -v
```

The .NET SDK 8 runs the engine-independent C# tests without Unity. The fixture
generator accepts only synthetic-source captures and a **new** output directory
under `hd2d/local/`. The native harness also refuses an existing output directory;
use new names on subsequent runs. Eighteen static cases receive their reference
pixels from the pinned native PPU, then independently reconstruct in C#. The
original raster-changing fixture is retained to test incomplete-support handling.
No reference PNG or binary capture is committed. `provenance.json` records the
synthetic source hash and each expected reference hash.

To qualify the actual Unity runtime on the Mac, close the project's Editor first
and run this in the logged-in desktop session (omit `-nographics`):

```sh
export X2_HD2D_FIXTURES="$PWD/hd2d/local/unity-fixtures"
"/Applications/Unity/Hub/Editor/6000.0.62f1/Unity.app/Contents/MacOS/Unity" \
  -batchmode -projectPath "$PWD/hd2d/unity" \
  -runTests -testPlatform EditMode \
  -testResults "$PWD/hd2d/local/unity-tests.xml" \
  -logFile "$PWD/hd2d/local/unity-tests.log"
```

All nine EditMode tests must pass: managed fixture parity, explicit raster
limitations, GPU parity for every static fixture, independent objects/visibility,
nonblack experimental GPU output through all four lighting stages, diagnostics
and baseline isolation during injected experimental failures, and Hierarchy OAM
selection mapping, deferred cleanup/reimport, and Play Mode guards/recovery.
The lifecycle test deliberately enters and exits Play Mode with domain and scene
reload disabled, temporarily restoring the previous Editor options afterward.
The lighting test uses a known visible original synthetic
sprite and checks exact baseline pixels after every stage. Missing fixtures or
a null graphics device fail explicitly. In an empty diagnostic scene, the Editor Test Runner can also
run the `Managed` and `Graphics` categories. Do not run graphics tests alongside
an already imported private scene: the prototype reserves Unity layers 8 and 9.

Also check the owner's normal Play Mode settings manually: import a synthetic
capture, enter Play Mode, verify that the inspector is paused and scene/setup
menus are disabled, then stop, reimport and export a zero-difference baseline.
There should be one resource-owner child and 128 OAM roots after reimport, with
no activation assertion or Editor scene-switch exception. The new lifecycle
tests and this manual check still require local Unity execution.

GitHub Actions runs the license-free native/managed tests. It does **not** claim
Unity compilation or GPU coverage. After successful owner qualification, record
the actual Unity/URP resolution, graphics API/device, XML results and a private
gameplay comparison's status/counts in the report; do not upload game imagery.

## Structure and attribution

`Core/` is pure C# with immutable imported state and separately derived component
data. `Runtime/` builds the quads, metadata, cameras and lighting experiment.
`Editor/` contains project setup, private-file inspection and comparison export.
`Tests/Editor/` contains the Unity qualification suite. Each has its own assembly.
The only saved scene contains the empty diagnostic root. Local pipeline assets
and machine-generated ProjectSettings are recreated by setup and ignored.

The format and graphics interpretation follow Matthew Stanley's X2Recomp and
the pinned snesrecomp PPU semantics. Existing repository licences, attribution,
permission and contribution terms apply unchanged. Capcom owns the original
game art; no game graphics are supplied in this project. Unity/URP retain their
own terms and are resolved by Package Manager rather than vendored here.
